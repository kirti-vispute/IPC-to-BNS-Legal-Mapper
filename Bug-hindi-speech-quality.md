## Problem and investigation

The selected Hindi path used pinned faster-whisper small (CPU/int8). It produced native-script text but repeated word errors on four licensed FLEURS Hindi clips; the downstream translator sometimes received corrupted meaning. This is an ASR problem before the unchanged legal analysis. Increasing beam size from 3 to 5 or disabling VAD did not improve aggregate word error on those clips; both slightly worsened the Hindi development set and Marathi. All audio stayed in ignored local diagnostic folders and never entered the legal corpus.

With the same decoding settings, pinned official faster-whisper medium (MIT, revision `4d9f76bb96174a5625e9ed85e89be563d98d528c`, local `model.bin` SHA-256 `9B45E1009DCC4AB601EFF815B61D80E60CE3FD8C74C1A14F4A282258286B51AE`) improved Hindi on all four development clips: mean character error 0.1635 -> 0.0870 and mean word error 0.4347 -> 0.2616. A separate, previously unseen four-clip Hindi FLEURS set improved on every clip: mean character error 0.2092 -> 0.1218 and mean word error 0.5044 -> 0.3229. These are normalized edit distances against dataset annotations, not legal-query or population accuracy. Speech files and measurements remain ignored under `output/voice-verification/`.

Marathi evidence did not justify switching: medium made one development clip Romanized and worsened development mean character/word error (0.2888/0.7976 -> 0.3791/0.8310), despite improving a separate set of four very short clips. Preserve small for Marathi.

## Decision and implementation

Use medium only when the user explicitly selects Hindi. Auto remains tiny with its confidence guard; selected Marathi remains small. `backend/core/transcriber.js` selects the pinned local model, reports the actual model name, and requires its files rather than silently downgrading. The Python speech worker, language metadata, native transcript review, text translation, date gateway, retrieval, citations and IRAC remain unchanged. `scripts/setup_local_speech.py` now downloads the pinned medium model for new installs. `frontend/app.js` gives selected Hindi a 190-second browser deadline; the backend worker gets 180 seconds rather than 120. Other language deadlines remain 130/120 seconds. An 86.2-second repeated-audio performance stress test took 116.8 seconds with medium, close to the old worker limit; this justifies the Hindi-only margin, not an accuracy claim.

Changed production/setup: `backend/core/transcriber.js`, `frontend/app.js`, `scripts/setup_local_speech.py`. Regression tests: `tests/transcriber.test.js`, `tests/voiceInput.test.js`.
